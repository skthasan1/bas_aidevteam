# Session note

Purpose: a short record of one working session, written at the end, so the history is searchable and the next session starts quickly. Save as `session-notes/<date>-<role>.md`. Keep a one-line index in the project's main briefing file instead of copying the note there.

```markdown
# Session <date>: <role>

## Summary
(Two or three lines: what the session achieved.)

## Work done
| Item | Link (issue / pull request / report) | Result |
|---|---|---|

## Findings raised
| Issue | Priority | Owner |
|---|---|---|

## Decisions
- Decision, who made it, where recorded.

## Tests run
- What, on which full commit, result. What was not run and why.

## Spend
- Amount, what for, who said yes, ledger link. "None" if none.

## Mistakes and lessons
- What went wrong, why, the rule or check that now prevents it.

## Next session should
1.
2.
3.
```

Rules: measured numbers only ("not re-measured" if you did not run the suite); no secrets; no personal data.
